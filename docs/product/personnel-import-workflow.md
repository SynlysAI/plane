# 人员录入与组织映射

系统管理提供“单条录入”和“批量导入”。两种入口都先生成待审核记录，尚未创建账号。

1. 单条选择学生或导师；学生填写姓名、邮箱、学号、小组及主导师，导师填写姓名、邮箱及主归属组织。已有导师按姓名搜索、邮箱核对；也可以填写新导师。
2. 批量上传成员名册及导师姓名邮箱表。上传区有默认关闭的“为已有账号重新生成初始密码”。未勾选时，当前工作区已有成员会作为问题行显示，不能再次纳入，已有密码保持不变；勾选后，这些已有账号可以纳入，并重新生成初始密码。已有导师可以被学生引用。存在同名导师且邮箱不同的情况时，需在审核行中明确填写邮箱。
3. 检查校验结果，逐行或筛选后全选，执行纳入/排除。勾选只选择操作对象；“已纳入 · 未导入”才表示审核决定已保存。编辑资料需要显式保存，保存后重新审核。
4. 所有行都已处理且至少纳入一人后，点击审批导入。核对纳入/排除名单、账号操作、小组、主导师、联合导师及拟新增关系。新建导师可指定主归属；未指定则待补齐，已有主归属不覆盖。
5. 点击“确认导入 N 名人员”。如人员或组织关系在预览后变化，重新打开预览核对。整批事务失败不会留下部分创建的账号。
6. 审批后可下载“本批次导入报告”，也可随时下载“全部初始密码”，并点击“查看组织关系”。两处下载的都是最近一次发放的初始密码，不是用户改密后的当前密码。新账号会写入该初始密码并要求下次登录修改；未勾选重新生成时，已有账号的资料和密码不覆盖。用户完成改密后，只有再次勾选重新生成，才能得到新的可登录初始密码。未发放过初始密码的活跃成员，全员下载中的密码列为空。

导入区的“下载全部初始密码”不依赖某一次批次，覆盖当前工作区活跃成员，列包括姓名、邮箱、人员类别、初始密码、仍须修改密码、来源批次。已停用账号不包含在内。只有账号管理员可以下载。直接导入命令默认拒绝已有成员；只有显式传入 `--reset-passwords` 才会轮换密码。

学生会成为所选小组的主归属成员；其主导师和联合导师加入该小组为导师角色，并分别建立具体师生绑定。组织角色不代表指导该小组所有学生。“成员与角色”显示人员类别、组织角色和具体指导关系；“直接导师”维护主导师及联合导师。

## 历史关系补齐

打开已导入批次，点击“检查导入关系”。勾选明确缺失的关系后确认补齐。已删除、已结束、组织失效、身份不明、已有其他主归属/主导师等冲突需人工处理，不能自动恢复或覆盖。操作有审计记录，可重复检查，不会重复生成关系。部署不会自动修改历史数据。

## 接口

均使用 `/api/research/workspaces/{slug}/user-imports/` 前缀及现有管理员权限。

- `POST single/`：JSON 单条录入，返回待审核批次；类别为 `STUDENT` 或 `ADVISOR`，组织使用 `org_unit` ID，导师使用 `advisors` 数组（主导师在前，可用已有成员 `id` 或新导师 `name/email`）。
- `GET {batch}/approval-preview/`：返回预览 `token`、`included`、`excluded`、`advisors` 和 `blockers`。
- `POST {batch}/approval-preview/`：保存 `advisor_primary_orgs`（邮箱到组织 ID）并返回新预览。
- `POST {batch}/approve/`：必须提交 `preview_token`；缺失或失效时返回冲突并要求重新核对。已成功导入的批次重复提交仍幂等返回。上传时的 `reset_passwords` 为真，才会轮换本次纳入的已有账号密码。
- `GET {batch}/report/`：本批次导入报告。名册行保存该次发放的初始密码快照；未发放密码的行留空。
- `GET /api/research/workspaces/{slug}/account-initial-passwords/`：当前工作区活跃成员的最近一次初始密码。普通成员返回 403。
- `GET {batch}/relations/`：返回关系预览 `token/items`，每项状态为 `missing/present/conflict`。
- `POST {batch}/relations/`：提交 `preview_token/item_ids`，仅补齐选中的无冲突缺失项。

旧文件格式和批量排除路由保留。行更新增加 `batch_detail`，批量审核增加 `batch`，历史列表增加 `review_counts`，供前端同步审核计数。前后端应配套更新。

## 验证

后端：在隔离测试环境运行 `test_research_import_workflow.py`、`test_research_user_import.py` 及组织权限契约测试。前端：运行 Web 组件测试、类型检查和针对性 lint。

`apps/web/tests/browser/import-workflow.fixture.tsx` 是浏览器隔离夹具，使用实际录入/审核组件及 189 行模拟名单，所有账号服务均被本地替身替换，不会操作真实账号。运行 `pnpm exec vite --config tests/browser/vite.config.ts` 后打开 `http://127.0.0.1:4175/import-workflow.html`；该入口不作为正式产品路由发布。
