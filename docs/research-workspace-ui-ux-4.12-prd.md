## 1. 文档定位与版本基线

### 1.1 一句话目标

在不降低科研信息密度、不改变业务能力的前提下，把 Research Workspace 从“功能完整、结构清楚的后台系统”精修为“克制、精致、高密度但容易捕捉重点的科研工作台”。

### 1.2 文档关系

- [`research-workspace-ux-guide.md`](./research-workspace-ux-guide.md) 是日常开发的权威 UX 规范。
- [`research-workspace-ui-ux-archive.md`](./research-workspace-ui-ux-archive.md) 只保留 4.10.0 与 4.11.0 的历史过程、验收与发布记录。
- 本文档规划 4.12.0 增量，不回写历史档案；后续若 4.12.0 实施完成，可再单独归档验收结果。

### 1.3 P1 / P2 范围口径

| 范围 | 状态       | 定义                                      | 本轮处理方式           |
| ---- | ---------- | ----------------------------------------- | ---------------------- |
| P1   | 已完成基线 | 4.10.0 与 4.11.0 已交付并验收的能力       | 只确认基线，不重复立项 |
| P2   | 未完成增量 | 4.12.0 需要补齐的视觉层级与信息可视化能力 | 本 PRD 的实际交付范围  |

P1 与 P2 的执行关系固定为：

```text
P1 已实现
↓
P2 只对现有组件做视觉与信息结构升级
```

因此 4.12.0 不重新开发 Workflow、Agent、页面壳或状态系统，只升级其呈现、分组、导航与可读性。

### 1.4 现状输入

本 PRD 基于以下三类输入：

1. 当前 `develop` 分支中的 Research Workspace 实现代码；
2. 4.10.0 视觉重构与 4.11.0 信息架构精炼的验收结论；
3. 三张现状截图：科研总览、研究链详情、组织架构。

截图仅作为问题证据。4.12.0 实施前必须在当前 `develop` 上重新采集截图；若截图与代码或 4.11.0 验收结论不一致，以代码与已验收文档为准。

## 2. 目标与非目标

### 2.1 产品目标

1. **快速捕捉重点**：信息量不明显减少时，用户仍能迅速识别当前对象、当前位置、待处理事项和下一步操作。
2. **建立视觉层级**：通过 Surface、Typography、Spacing、Alignment 和信息分组形成稳定层级，而不是依靠大量边框与卡片切割页面。
3. **真正可视化 Workflow**：研究链打开即能理解完整流程、已完成阶段、当前位置、阻塞点和后续阶段。
4. **轻量化 Agent**：Agent 作为当前科研场景的侧边能力存在，默认精炼、可呼出、继承上下文，不成为第二工作台。
5. **全 Workspace 一致**：三核心页先行打样，其余列表、详情、项目与设置页按同一视觉基线扩散。

### 2.2 非目标

- 不新增业务功能。
- 不修改 API、权限、状态流转、排序、业务对象和数据模型。
- 不重造 Plane Design System 或全局主题。
- 不通过删除信息制造“空旷的极简”。
- 不做 AI 官网、AI Dashboard、科技风产品或高饱和彩色仪表盘。
- 不引入渐变、发光、霓虹、玻璃拟态、装饰粒子、AI badge、巨型图标或复杂装饰动画。

## 4. P2：未完成增量需求

P2 是 4.12.0 的实际交付范围。它解决的不是“功能缺失”，而是“复杂信息还没有被足够好的视觉结构组织起来”。

### 4.1 核心问题

1. 页面内容多、模块多、状态多、操作多时，大量信息仍处于相近的白色 Surface 中，眼睛不知道先看哪里。
2. 研究链虽已有节点导轨，但还需要从“节点列表”进一步升级为“一眼可读的科研流程地图”。
3. Agent 已有侧边抽屉，但内部信息与运行细节的默认层级仍需更轻、更符合插件形态。
4. 列表、详情、设置等外围页面还需要统一套用三核心页沉淀出的视觉基线。

### 4.2 P2-01 Surface 与信息分组

#### 需求

- 建立页面背景、Primary Surface、Muted Surface 与低饱和状态背景的稳定层级。
- 同语义信息合并为一个大区块，用间距、标题、背景和 subtle divider 分组。
- 减少无语义 Card、嵌套边框和重复 divider。
- 状态背景只允许低饱和 success / warning / danger / accent 语义色。
- 所有颜色必须映射到 Plane semantic token，禁止硬编码色值。

#### Surface 语义

| 层级              | 用途                       | 视觉预期           |
| ----------------- | -------------------------- | ------------------ |
| Page Background   | 页面画布与 Supporting 信息 | 最安静             |
| Primary Surface   | 主要工作区与核心对象       | 主内容承载面       |
| Muted Surface     | 次级信息、元信息、运行详情 | 弱化但不模糊       |
| Status Surface    | 待处理、异常、完成、当前   | 低饱和、小面积     |
| Interactive Hover | 行、节点、列表项悬停       | 微妙变化，不改布局 |

#### 对比原则

Surface 不是单纯换一种白色。相邻语义区域必须能被肉眼快速区分，但对比保持低饱和、低刺激。Primary、Secondary 与 Status 区域允许使用明确但克制的背景差异，使用户无需逐个阅读标题即可识别信息组。

目标不是“无边框极简”，而是“有层次的克制”。禁止把现有卡片简单替换为一大片白色区域加 subtle divider；如果移除边框后信息组不可辨认，必须改用 Surface 差异、标题、间距或背景层级补足。

#### 验收

- 每个视图内 Primary 对象唯一。
- 相邻卡片若语义相同，应合并或明确说明为什么必须独立。
- 相邻 Primary、Secondary、Supporting 与 Status 区域不依赖边框也能被快速区分。
- 页面灰度化后仍能分辨主要工作区、次级信息和状态信息。
- 不出现彩色卡片阵列、大面积高饱和色块或装饰性色块。

### 4.3 P2-02 Typography 层级

#### 需求

建立从 Object 到 Metadata 的稳定文字层级，层级优先来自排版，而不是颜色或大量加粗。

| 层级                  | 内容                        | 视觉预期                    |
| --------------------- | --------------------------- | --------------------------- |
| Object Title          | 页面对象、课题、报告标题    | 最强标题层级，可读而非巨大  |
| Section Title         | 区块标题                    | 清楚但明显低于 Object Title |
| Key Data / State      | 数字、当前节点、关键状态    | 可快速扫描，与正文拉开差距  |
| Body                  | 说明、摘要、列表主字段      | 适合连续阅读                |
| Metadata / Supporting | Owner、时间、范围、ID、提示 | 弱化、紧凑、不抢焦点        |
| Action                | 主操作与次级操作            | 操作语义清楚，不伪装成标题  |

#### 验收

- 标题、正文、Metadata 不使用接近的字号、字重与颜色。
- 不通过连续加粗解决层级问题。
- 数字统计具备统一格式与稳定宽度。
- 状态文字始终与状态语义配合，不能只靠颜色表达。

### 4.4 P2-03 排版、对齐与 Vertical Rhythm

#### 需求

- 统一页面左右边界、内容宽度、行高与区块间距。
- 标题、说明、正文、Metadata、按钮之间的距离遵循语义关系。
- 日期、数字、时间与操作列稳定右对齐，数字使用等宽数字。
- 长文本 truncate 并保留可访问的完整标题。
- 操作区保持固定位置，不因内容长度漂移。
- 主要区块、相关条目、标签与数值使用稳定间距梯度。

#### 验收

- 同一页面内不出现随机 padding 和无解释的间距跳变。
- Grid / List 的列起点、基线和结束位置对齐。
- 滚动容器内不出现横向破版。
- 信息密度保持研究工作台标准，不用大面积空白制造“高级感”。

### 4.5 P2-04 状态系统精修

#### 需求

- 统一已完成、进行中、等待人工、需修订、失败、草稿、归档等状态的视觉语言。
- 状态表达同时包含文字、低饱和背景或指示符，保证非颜色通道可识别。
- 待处理、异常、人工决策优先于普通状态获得视觉注意。
- 当前节点的“真实当前位置”与用户临时点击查看的节点必须区分。

#### 验收

- 状态含义不需要猜测。
- 异常与待人工处理状态在缩略图中仍可辨认。
- 当前节点使用唯一 accent 或等价强层级，不与选中态混淆。
- 状态不使用 Glow、霓虹边框、大面积高饱和背景或夸张阴影。

### 4.6 P2-05 科研总览精修

#### 信息层级

```text
第一层：当前科研 / 当前任务
第二层：待处理事项
第三层：科研概况
第四层：Supporting 信息
```

#### 第一层：当前科研 / 当前任务

必须突出：

- 当前课题。
- 当前研究链。
- 当前节点。
- 当前状态。
- 最重要的下一步操作。

用户进入页面后，应在 3 秒内回答“我现在做什么、卡在哪里、下一步点什么”。

#### 第二层：待处理事项

必须突出：

- 待确认。
- 待审批。
- 待人工决策。
- 异常或外部系统降级。

要求使用克制的状态背景与清晰操作入口，不让辅助统计与待处理事项竞争注意力。

#### 第三层：科研概况

将成员、项目、报告、阶段、评审、审批等信息聚合为紧凑 Overview 区域：

- 使用“数字 + 标签 + 简短说明”。
- 使用单行或紧凑分组，不做六个等权重大卡片。
- 每个数字必须有明确统计口径与时间范围。

#### 第四层：Supporting 信息

组织范围、近期成果、导航、筛选历史、低频入口允许：

- 紧凑展示。
- 折叠展示。
- 放入弱化 Surface。

但不得删除用户已有权限可见的信息，除非该信息已被更高层级等价覆盖。

### 4.7 P2-06 研究链 Workflow 精修

本轮为 P1 现有 `ResearchChainWorkflowRail` 的 UI 与信息结构精修，不得重新创建平行 Workflow 实现。

#### 三重职责

Workflow Rail 同时承担：

1. **全局流程认知**：研究走完整条科研主链需要经历哪些阶段。
2. **当前位置识别**：当前研究处于哪一阶段，是否阻塞或等待人工处理。
3. **阶段导航**：点击历史或后续阶段查看该阶段摘要与关联节点。

Workflow Rail 不是装饰 Stepper，也不是普通进度条；它是研究链的一级信息结构和主导航结构，不能放在普通节点列表之后，也不能隐藏在二级区域。

#### 定位

Workflow Rail 是全局流程地图；Current Node 是当前工作区。两者不能混在同一视觉层级。

```text
研究链 Header
↓
完整 Research Workflow
↓
Current Node
↓
Node Detail
↓
Input / AI Action / Intermediate Product / Validation / Human Decision / Output
↓
Activity / Trace
```

#### 科研主 Workflow 固定骨架

研究链顶部 Workflow 必须以科研主链作为稳定视觉骨架：

```text
文献调研
→ 选题
→ 评估
→ 预实验
→ 分析
→ 开题
→ 实验
→ 分析
→ 迭代
→ 总结
→ 论文写作
→ 结题
→ 转化
```

这 13 个阶段是 Research Workspace 的统一科研过程表达，不是新增业务对象，也不要求当前数据库已经存在全部节点。Workflow 不按“当前数据库恰好返回哪些节点”动态缩短。

必须保留两个“分析”阶段：第一个分析对应预实验后的分析，第二个分析对应实验后的分析。两者不能因为名称重复而合并。

#### 主链阶段与现有节点映射

| 主链阶段         | 现有节点映射                       |
| ---------------- | ---------------------------------- |
| 文献调研         | `LITERATURE_REVIEW`                |
| 选题             | `TOPIC_EVALUATION` 的选题决策部分  |
| 评估             | `TOPIC_EVALUATION` 的评估结论部分  |
| 预实验           | `PRE_EXPERIMENT`                   |
| 分析（预实验后） | 结构上紧跟预实验的 `ANALYSIS`      |
| 开题             | `OPENING`；`PLAN` 作为准备关联节点 |
| 实验             | `EXPERIMENT`                       |
| 分析（实验后）   | 实验或迭代后的 `ANALYSIS`          |
| 迭代             | `ITERATION`                        |
| 总结             | `SUMMARY`                          |
| 论文写作         | `PAPER_WRITING`                    |
| 结题             | `COMPLETION`                       |
| 转化             | `TRANSFER`                         |

映射规则：

- `TOPIC_EVALUATION` 可同时关联“选题”和“评估”两个视觉阶段，但必须展示共享关联，不得伪造两个业务节点。
- 当 `TOPIC_EVALUATION` 处于 `DRAFT` 或 `ACTIVE` 时，当前阶段显示在“选题”；进入等待人工、需修订、失败或完成后，实际状态显示在“评估”，“选题”显示为已完成。
- 两个“分析”阶段通过节点在 Chain 中的前后关系区分，而不是仅靠标题猜测。
- `RESEARCH` 或无法唯一映射的节点，按最近的前后语义阶段归入对应阶段摘要；仍无法判断时保留在节点详情列表并标记“未映射”，不得伪造主链状态。
- 主链阶段只展示由实际节点推导出的状态、时间与产物；没有实际节点时显示“未开始 / 未进入”。
- 映射逻辑必须是纯展示层推导，不修改后端数据模型、节点顺序和状态流转。

#### 需求

1. **完整流程可见**
   - 固定展示 13 阶段科研主链。
   - 现有 Chain 节点映射到对应主链阶段。
   - 尚未产生实际节点的阶段显示为未开始 / 未进入。
   - 不伪造不存在的执行结果、时间或产物。
2. **流程关系可读**
   - 体现方向、阶段关系、完成状态、当前位置和未来阶段。
   - 不得退化成简单并列的节点按钮。
3. **当前位置突出**
   - 当前真实节点一眼可见。
   - 当前节点与选中查看节点、悬停节点、未来节点语义分明。
4. **点击行为稳定**
   - 点击历史或未来节点只查看摘要与关联信息。
   - 不跳出当前研究链。
   - 不改变真实当前节点，不触发状态流转。
5. **桌面可用**
   - 1440 / 1920 宽度下优先横向完整展示。
   - 空间不足时允许横向滚动。
   - 不把节点压缩到不可读，不隐藏状态文字。

#### 状态语义

| 状态     | 表达                                    |
| -------- | --------------------------------------- |
| 已完成   | muted + completed indicator             |
| 当前     | 唯一 accent / current indicator         |
| 待人工   | 低饱和 warning + 明确文字               |
| 失败     | 低饱和 danger + 明确文字                |
| 未来     | neutral / muted，不显示执行结果         |
| 临时查看 | selected indicator，不覆盖 current 语义 |

### 4.8 P2-07 Agent Side Panel 精修

本轮为 P1 现有 `ResearchAgentSidePanel` 的 UI 精修，不得重新创建平行 Agent 实现。

#### 形态

- 保持右侧 Side Panel / Drawer 插件形态。
- 宽度 360–440px，不占据整页。
- 默认关闭，可从当前研究链场景呼出。
- 打开时主科研页面不跳转、不被替换。
- 优先使用 overlay 或稳定 Side Panel 交互，主内容区域不因 Panel 出现而剧烈重排。
- 独立完整 Agent 路由保留，用于高级或全量任务。

Agent Panel 打开后，核心对象、Workflow Rail 与当前节点不得发生明显跳动，避免用户丢失科研上下文。

#### 默认信息层级

```text
Agent Header
↓
当前上下文摘要
↓
Conversation / Result
↓
固定输入与关键操作
↓
可折叠运行详情
```

#### 需求

- 自动继承当前课题、研究链、节点或对象上下文。
- 默认只展示用户当下需要阅读的内容。
- Tool Call、Trace、Runtime、Artifacts、装配详情默认折叠。
- 待审批或需要人工处理的信息保持可见。
- 输入区固定在底部，长对话滚动不导致输入漂移。
- Panel 内部同样执行 Surface、Typography 与 Alignment 规范。

#### 验收

- Panel 打开前后，主内容中的核心对象、Workflow Rail 与当前节点保持稳定。
- Panel 关闭后，主页面回到可继续科研工作的状态。
- Panel 不遮挡当前节点的主操作；若小屏无法避免遮挡，必须提供明确关闭路径。

#### 禁止项

- AI Glow。
- 渐变背景。
- 玻璃拟态。
- 大型 AI 图标。
- 复杂装饰动画。
- “Powered by AI”式装饰标签。

### 4.9 P2-08 全 Workspace 组件与页面精修

#### 列表页

适用于 Chain 列表、报告、审批、评审、项目、实验、文献、成果、代码等列表：

- 统一标题链接、状态徽标、Owner、日期、操作列。
- 数字与日期右对齐。
- 行 hover 微妙，不改变行高。
- 筛选 chips、搜索、空态、加载态、错误态与权限态使用统一出口。
- 批量操作出现时不得造成列宽跳动。

#### 详情页

适用于报告详情、实验详情、材料详情、阶段详情等：

- Header 只保留 Object、Context、主操作。
- 元信息进入紧凑区域，不占据主标题行。
- 关联对象按输入、过程、验证、输出、决策等语义分组。
- 历史与 Trace 默认折叠或放入次级区域。

#### 项目与阶段页

- 项目切换、阶段导航、材料层级保持稳定边界。
- 阶段进度使用低饱和流程表达。
- 材料和实验记录优先采用结构化列表或表格，不逐条做卡片。
- 长表单按语义分段，减少连续输入造成的疲劳。

#### 设置与支撑页

- 沿用 Plane settings 布局语言。
- 组织树、成员、角色、模板、身份、平台、集成、审计等页面统一信息分组。
- 高频主操作唯一，低频操作收入次级菜单或图标按钮。
- 组织树等重复入口不得造成整页操作噪音。
- 审计与日志保持表格化、时间对齐和状态过滤一致性。

## 6. 实施顺序与视觉 review 流程

### 6.1 Phase 0：冻结基线

1. 在当前 `develop` 采集三核心页 1440 / 1920、浅色 / 深色截图。
2. 建立 P1 能力回归清单。
3. 为每页填写信息分级表：Primary、Secondary、Supporting。
4. 冻结 13 阶段主链与现有节点类型的映射用例，覆盖空 Chain、只有当前节点、重复分析节点、等待人工、失败与归档。
5. 标记现有 Surface、Typography、对齐和状态问题。
6. 确认无业务文件需要修改；若发现必须改业务逻辑，停止并回到需求评审。

### 6.2 Phase 1：视觉基线与组件映射

1. 梳理 Plane semantic token 与现有组件映射。
2. 定义 Surface、Typography、Spacing、Alignment、状态的实现口径。
3. 将 Twenty、Kaneo、Outline、Huly、AppFlowy 的参考维度转成页面级检查项，再落回 Plane / Propel 组件。
4. 只在现有语义组件或 Plane 组件不足时新增组件。
5. 补充组件级视觉约束与测试用例，不引入平行实现。

### 6.3 Phase 2：Wave A 三核心页

1. 精修科研总览四层信息结构。
2. 精修研究链 Header、Workflow Rail、Current Node 与节点详情分层。
3. 精修 Agent Side Panel 默认信息与折叠运行详情。
4. 每页完成后立即截图、灰度、缩略图和交互检查。
5. 通过后再进入 Wave B。

### 6.4 Phase 3：Wave B 工作对象页面

1. 先处理高频列表与详情页。
2. 统一表格、筛选、空态、状态、Metadata 与操作列。
3. 按对象类型套用详情页结构，不做逐页局部风格。
4. 保留必要业务差异，避免为了统一而破坏专业语义。

### 6.5 Phase 4：Wave C 设置与支撑页面

1. 处理组织、系统、模板、身份、平台、集成、审计页面。
2. 降低重复操作噪音，统一表单分组与次级操作。
3. 保持设置页与 Plane 原生布局的连续性。
4. 回归共享组件影响的非科研页面。

### 6.6 Phase 5：产品级视觉验收

1. 全页面截图矩阵复查。
2. 灰度与缩略图检查。
3. 深浅色主题检查。
4. 1440 / 1920 响应式检查。
5. 键盘与辅助技术检查。
6. 回归 P1 组件测试与业务行为。
7. 更新 4.12.0 验收报告与 UX 指南。

## 7. 验收标准与成功度量

### 7.1 三核心页验收

#### 科研总览

用户进入页面后 3 秒内可以找到：

- 当前课题。
- 当前节点。
- 待处理事项。
- 下一步操作。

同时统计、组织、成果等辅助信息仍存在，但不与 Primary Content 竞争焦点。

#### 研究链

用户无需跳转即可理解：

- 固定 13 阶段完整主链。
- 已完成内容。
- 当前位置。
- 待人工处理或失败的位置。
- 后续阶段。

两个“分析”阶段同时可见且语义分明。当前真实节点、临时查看节点与共享关联节点不会混淆。Workflow 同时完成流程认知、当前位置识别与阶段导航。

#### Agent

- 默认关闭或轻量可呼出。
- 打开后不离开科研主流程。
- 打开前后主内容的核心对象、Workflow 与当前节点不明显跳动。
- 自动继承上下文。
- 默认只展示当前有用的对话与结果。
- 运行详情可展开但不制造噪音。

### 7.2 全局视觉验收

- [ ] 灰度下层级清晰。
- [ ] 缩略图中仍能识别页面类型与 Primary 对象。
- [ ] 层级主要来自排版、留白、对齐与 Surface。
- [ ] 边框、卡片和 divider 数量得到克制。
- [ ] 状态色低饱和且仅表达语义。
- [ ] 1440 / 1920 可用。
- [ ] 深浅色主题均可用。
- [ ] 无硬编码色值。
- [ ] 无渐变、发光、玻璃拟态、AI badge、装饰动画或多彩 KPI。
- [ ] 研究者长时间使用不产生明显视觉疲劳。

### 7.3 功能与工程质量验收

- P1 组件测试全部通过。
- 相关页面现有业务测试通过。
- 不改变 API contract、权限行为、状态流转与业务排序。
- 不新增重复组件或手写平行表格。
- TypeScript、lint、format 检查通过。
- 共享组件修改完成受影响模块回归。

### 7.4 成功度量

| 维度       | 度量方式                                                       |
| ---------- | -------------------------------------------------------------- |
| 重点捕捉   | 三核心页截图 3 秒 review 能否说出当前对象、状态和下一步        |
| 信息密度   | 不删除权限内信息，页面高度增长不超过精修前的 15%               |
| 视觉一致性 | Wave A–C 页面通过同一 Surface、Typography、Alignment checklist |
| 重复实现   | 新增平行组件数量为 0                                           |
| 硬编码风险 | 新增硬编码色值为 0                                             |
| 回归风险   | P1 测试与业务行为回退数量为 0                                  |

页面高度增长阈值是设计约束而非业务指标；若某页确需更多空间，必须在视觉 review 中说明原因并记录例外。

## 8. 风险与依赖

| 风险                     | 影响                 | 缓解措施                                         |
| ------------------------ | -------------------- | ------------------------------------------------ |
| 信息密度与可读性冲突     | 页面变空或变乱       | 先组织信息，再考虑删减；保留权限内信息           |
| 视觉统一削弱专业语义     | 不同对象难以区分     | 统一基础层，保留对象必要差异                     |
| Workflow 被做成装饰组件  | 流程看似好看但难理解 | 固定 13 阶段骨架，同时承担认知、定位与导航       |
| 主链映射与历史数据不唯一 | 阶段状态误判         | Phase 0 冻结映射用例；无法判断时标记未映射       |
| Agent 信息折叠过度       | 用户找不到错误或审批 | 错误、待人工决策与关键结果保持默认可见           |
| 共享组件修改影响原生模块 | 非科研页面回归失败   | 优先页面级组合，修改共享组件时补充回归           |
| 设置页操作收纳过度       | 高频管理动作变慢     | 高频操作保持一级入口，低频操作才收纳             |
| 截图基线过期             | 误判已完成能力       | Phase 0 重新采集截图，以当前代码与 4.11 验收为准 |
