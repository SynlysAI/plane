# MCP 客户端确认调整与验证

日期：2026-10-23（Asia/Shanghai）。基线：develop `4a604b63`。完成本地验收，远端测试服务器尚未部署。

## 行为

科研 HTTP API 和 MCP 共用 `ResearchOperationService`，采用“准备不可变提案 → Agent 客户端落实用户授权 → 提交原 operation_id 执行”。平台收到有效节点写授权的 execute 请求即可校验并执行，不再要求 Plane 人工审批记录。已有明确用户授权覆盖操作时，客户端无需再次询问；服务端不能验证客户端是否显示了确认界面。

prepare 仍只保存提案及审计；execute 才写业务数据。返回增加 `confirmation_mode=agent_client`；兼容保留 `review_path`，其用途为查看节点。HTTP 和 STDIO 的工具说明均已同步。

保留成员及节点权限、写入范围、部署及工作区开关、撤销、提案有效期、不可变哈希、来源与目标前置条件、事务、重复执行保护和读回。已拒绝或取消的提案仍禁止执行。旧 `decision` 接口及审批记录保留兼容，但不再是执行前置步骤；历史审批记录过期也不要求再次进行平台审批，提案本身的有效期仍受检查。

新来源事件记录实际执行用户与 `authorization_source=agent_client`，不创建虚假的人工审批记录。历史实际存在审批记录时才附带 `approving_user_id`。

## 本地真实 MCP 验收

使用用户明确提供的节点连接，调用原生 MCP HTTP JSON-RPC；没有调用平台 `decision` API。

- 读取科研链、节点上下文、任务、事件、快照和资源列表；报告反馈列表为空时正常返回。
- 在“文献调研”测试节点创建带测试标记的任务、追加评论、保存引用任务正文的分析草稿和追加过程记录，四类写入均 `COMMITTED`、读回 `verified`。
- 重复 prepare 和 execute 返回同一提案及业务对象；评论和过程记录未重复。
- 取消提案后执行、替换同 request_id 的内容、越权节点、无效参数和不存在的关联资源均正确拒绝。
- 操作与事件分页正常。

真实节点内没有现成的允许关联资源，因此未进行真实资源的成功关联；该正向流程已由 PostgreSQL 合约覆盖。测试任务、评论、草稿和记录保留供用户查看，均标明本地功能测试用途，不代表科研结论。连接密钥与私密配置不进入提交。
