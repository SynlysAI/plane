# MCP 连接设置：配置回看与长期授权

日期：2026-10-30。本文适用于本轮源码；尚未部署到现有服务，也未提交或推送。历史文档中的“一次性配置”和短期有效期不再适用于新版项目连接与周报连接。原节点授权、个人 API 令牌与独立行政门户继续使用各自规则。

## 页面行为

个人设置的 MCP 配置保留“项目连接／周报连接”页签。先选择工作区、访问权限、范围及有效期，点击“创建连接”，再在弹窗内填写名称、核对摘要并“确认生成”。取消不创建，提交期间防止重复操作。

两类连接共用左列表、右详情，移动端使用列表与详情切换。详情保留授权范围、状态、创建时间、到期时间和最近使用时间。配置支持 Codex TOML／通用 MCP JSON、显示、复制、导出及隐藏。列表只持有元数据；配置仅在创建成功或显式查看时进入内存，切换连接、账号、工作区、页签、关闭设置或离开页面时清除。到期时清除已展示的配置，迟到响应不能恢复旧密钥。

“连接”是授权记录，“服务地址”是客户端调用入口，“访问密钥”是鉴权凭据。行政任务支持直接创建、修改、状态流转与评论；科研任务支持直接修改和状态流转，创建、评论、资源关联、分析等操作沿用提案流程。周报的“保存草稿”和“正式提交”独立授权，彼此不隐含。

## 管理接口

项目管理前缀为 `/api/mcp/connections/`；周报管理前缀为 `/api/research/workspaces/<slug>/mcp/weekly-report/connections/`。以下接口均限定本人会话，不接受机器密钥替代登录。POST 还需同会话的 `X-CSRFToken`。

| 方法 | 相对路径              | 行为                                                                                 |
| ---- | --------------------- | ------------------------------------------------------------------------------------ |
| GET  | 空路径                | 元数据、`configuration_available`、`next_cursor` 和 `csrf_token`；无密钥、摘要或密文 |
| POST | 空路径                | 创建连接；项目名称为 `name`，周报名称为 `label`                                      |
| POST | `<id>/configuration/` | 空对象 `{}`，按需取回完整配置                                                        |
| POST | `<id>/rotate/`        | 空对象 `{}`，原子重置摘要和密文，返回新配置                                          |
| POST | `<id>/revoke/`        | 空对象 `{}`，撤销并清除可恢复密文                                                    |

`ttl_days` 可取 `1`、`7`、`30`、`365` 或 `null`，页面默认 `365`；`null` 表示永不过期，响应 `expires_at` 也为 `null`。项目旧请求省略该字段时默认一年；周报创建仍需显式传入该字段。旧连接的原有权限和到期时间不追溯改变。

旧连接 `configuration_available=false`，需用户确认重置密钥后才支持回看。重置保留连接 ID、权限和原期限，新请求不再接受旧密钥；不取消已鉴权且在执行中的请求，也不撤销已提交业务结果。配置或审计失败会回滚事务，保留原密钥。过期、撤销连接仍可查看授权详情，但不能回看配置或重置密钥。

列表按创建时间和 ID 稳定倒序分页，项目每页默认 20 条、可用 `limit=1..50`，周报每页 30 条。游标有效一小时并绑定本人，周报另绑定工作区；旧版游标失效时刷新列表。项目响应批量附带当前仍可访问的工作区名称，不依赖创建表单的候选分页。

管理请求超时统一为 30 秒。创建结果不确定时刷新列表、人工核对并通过配置回看恢复，不自动重复创建。重置超时也先回看当前配置，避免重复重置。MCP 工具本身的客户端执行超时沿用原配置，不与管理页面的 HTTP 超时混淆。

## 凭据与权限

两类连接使用现有 Fernet 加密能力存储 `token_encrypted`，摘要仍用于机器鉴权；加密后执行恢复核验，失败不创建。加密依赖现有 `SECRET_KEY`，升级需保持其稳定，备份与数据库一并按既有私密配置流程保管。变更该值会导致原密文不可恢复，此时需本人确认重置密钥。

配置响应保留 `Cache-Control: no-store` 和 `Referrer-Policy: no-referrer`；日志中间件跳过这些凭据接口正文，审计仅存连接和操作摘要。前端不将真实密钥写入 localStorage、URL 或列表缓存。

永久连接仍受账号活跃状态、成员资格、私有工作区准入及业务权限约束，并计入现有连接数量限制。周报候选、创建和机器调用均复核私有工作区准入。功能关闭后，有效成员仍可查看和撤销本人连接。周报提案最多有效十五分钟，也不能超过有限期连接剩余期限；科研提案沿用原独立期限。

本轮服务审查还修正了永久连接的执行前复核、科研和周报数量限制、分页稳定性、中文禁用原因、失败恢复及跨账号异步响应隔离。周报原有全表一致性屏障继续保留；此次没有改变锁协议，不能据此宣称容量或并发性能已提升。

## 迁移与发布

增量迁移 `0215_mcp_recoverable_credentials` 依赖 `0214_user_background_asset_type`，只增加密文字段并使两类连接的到期时间可空。旧记录密文默认为空，摘要、范围和期限保持原值。

先更新兼容后端并应用迁移，再更新前端。当前混合部署将 API 源码挂载进容器，执行迁移和重启仍应使用仓库既定部署流程，避免新代码先于 schema 接收请求。本轮没有操作生产迁移或重启服务。

已有 `expires_at=NULL` 时不能直接恢复要求非空到期时间的旧 schema／旧代码。优先保留兼容后端和 schema、回退前端；如确需逆迁移，先制定并批准永久连接的处理方案。逆迁移还会丢失可恢复密文，不能当作无损回退。后续推送时按当时版本基线同步提升次版本号。
