# 行政项目隔离与旧 Plane 数据清理（4.27.1）

## 业务范围

存在科研档案或科研链关联的底层 Project 属于科研范围，关联被软删除也不改变分类。行政项目入口使用 `scope=administrative`；共享 Project 接口和缓存仍供科研链使用。工作区视图、分析概览、活跃项目、保存分析和导出均在原权限范围内附加未归档行政项目限制。

人员统计按当前可见未归档行政项目中的有效成员去重，排除失效账户和机器人，同一用户取最高项目角色。无行政项目时所有指标为零。

## 清理命令

```bash
python manage.py cleanup_legacy_plane_data --workspace public
python manage.py cleanup_legacy_plane_data --workspace public --apply
```

默认仅预览。输出 JSON 包含目标项目、逐模型删除 ID 和保留资源的数量、内容 SHA256。显式 `--apply` 才在事务中删除；保护检查失败或清理前后指纹不一致会中止并回滚。再次预览应没有新增删除。

删除范围包括科研 Project 下旧工作项（含归档、软删除）、评论、历史、关联、周期、模块、项目视图、标签、旧页面及相关业务记录。保留 Project、成员权限、项目标识和个人设置、State 基础配置、所有科研模型，以及科研引用和行政共享的页面、父页面及附件。二进制正文也纳入内容校验。不直接删除对象存储文件。

若科研资料仍引用某个拟删工作项或附件，或级联会影响行政记录，预览即中止。应核查引用后修订清理范围，不得绕过保护检查。
