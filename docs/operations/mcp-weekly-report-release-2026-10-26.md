## 配置与使用

前提：用户是有效工作区非访客成员，有有效组织归属和报告能力；本人周报连接只支持 WEEKLY、本周/上周。周期按工作区报告时区解释。

1. 在“设置 → MCP 连接 → 周报连接”选择工作区，填写名称，分别选择保存草稿/正式提交，只选择实际需要的动作及后端允许的期限。
2. 生成后保存 TOML 或 JSON。密钥仅返回这一次，关闭结果、切页、切工作区或关闭弹窗后无法找回；丢失时先撤销旧连接再创建。不要把配置粘贴到工单、日志或公开仓库。
3. HTTP 使用签发返回的专用地址与 `X-Weekly-Report-Token`；不要改成原节点 MCP 地址，也不要同时附加普通 API key 或旧节点凭据。
4. STDIO 使用原 demo 环境运行 `demos/sciencediscovery-plane-mcp/weekly_report_mcp.py --config <私密配置文件>`；身份参数只用 PLANE_BASE_URL、PLANE_WORKSPACE_SLUG、WEEKLY_REPORT_TOKEN，示例见 API v1 文档。
5. 修改客户端连接配置后，断开并重新连接该 MCP 服务，刷新工具目录。应发现恰好五个 weekly_report 工具；只有 context/get-operation 是只读。若仍显示旧节点工具，检查客户端实际加载的服务名、地址和配置文件，不通过扩大旧节点权限来修复。
6. Agent 应先 context，再 prepare 固定周期/正文，展示完整提案和副作用，按用户授权执行同一 operation_id。Plane 设置子页不增加正文确认界面。

### 失败恢复

| 情形                         | 操作                                                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| 创建连接超时                 | 先刷新本人连接列表核对；不自动再次签发。无法取回密钥的连接可撤销，再明确创建新连接。                   |
| prepare 超时                 | 用相同 request_id、相同参数恢复，不换 ID；参数不同会冲突。                                             |
| execute 超时或 retryable 503 | 查询原 operation_id；PROPOSED 才考虑重试原操作。不要自动准备新操作。                                   |
| COMMITTED/readback=pending   | 已提交成功，保存原结果并继续查询该操作，不重提报告。                                                   |
| revision 冲突 / 策略变化     | 重新取 context，核对当前正文与受众，重新准备并按用户授权执行；不静默覆盖网页修改。                     |
| SUBMITTED / ACCEPTED         | 不能直接覆盖；需修改时沿用正常退回流程，重提追加新版本。                                               |
| 凭据过期、撤销或全局关闭     | 机器查询也可能拒绝。通过原登录态网页、管理元数据及受权限约束的运维记录核对结果；新凭据不能接管旧操作。 |

## 生产启用前的要求

当前不能直接全量启用，至少需要处理/接受以下事实：

1. **全表屏障风险**：grant 签发与 prepare/execute 会锁 Page、报告及相关策略表；会影响其他工作区。争用正确性已测，容量、长期运行和实际业务写入延迟未测。要么在保持同等一致性保障的前提下收窄锁协议并回归，要么限定到独立、受控低并发环境并有明确运维接受与监控；不得仅删除锁或 revision 检查。
2. **灰度能力边界**：目前只有全局 `RESEARCH_WEEKLY_REPORT_MCP_ENABLED`，没有独立的周报 MCP 账号/工作区 allowlist。启用后所有满足既有报告权限的用户可签发。不能声称该变量只为一个测试账号开放；现阶段可在隔离实例灰度。共享生产实例若需精确灰度，需要另行实现后端限制；不要通过关闭正常周报能力来伪造灰度。
3. **已有界面问题**：作者详情页显示“正式版本 v—”，因为现有 ReportBody 的标签只读 official_content.version_no，而现有 serializer 对作者返回 draft_content。导师视图 v1/v2、数据库 Snapshot、MCP 结果版本号正确；本阶段遵守“不改详情/编辑器”的约束，未改这个标签。此代码路径同样适用于普通网页 REST 报告，不是 MCP 专有分支。
4. **未覆盖项**：真实窄屏/触摸设备、其他浏览器、第三方 Agent 产品 UI 中的工具审批/刷新、正式反向代理/TLS/域名、真实对象存储、外部通知投递与 worker 崩溃、长时间压力测试。现有原连接门户在隔离环境没有配置，不能把原页面正常挂载或代理单测等同于真实旧门户网络验收。
5. **已有测试失败**：阶段 3 的科研链详情 12 项原版同名失败和阶段 1 图片夹具的 10 项原版失败继续按历史记录处理。阶段 4 没有改这些无关组件/夹具，也没有重跑全仓并声称全绿。

本次真实网络素材引用使用 source_refs=[]；带素材的权限/版本校验有本次后端回归，未另用真实节点客户端串联取材。浏览器正文覆盖基础标题/段落，没有逐个手测全部 Markdown 子集节点；大列表分页、TOML 和异常签发竞态以自动回归为主。

### 关闭与回滚

- 将生产配置中的独立周报开关关闭并通过既定流程使 API 生效。旧节点/原连接协议使用各自开关；不要为关闭周报而关闭所有报告或节点功能。
- 有效成员仍可登录管理页列出/撤销本人连接；逐条撤销不再需要的凭据，并从客户端删除本地配置/下载文件。重新打开全局开关不会自动取消旧 grant 的撤销状态。
- 关闭/撤销不会撤回已提交周报。已提交 Report、正式 Snapshot、审核历史、审计、站内 Notification 和 COMMITTED 结果应保留；业务修订沿用现有报告流程。
- **不要把逆迁移 0201 当普通功能回滚**：它会删除独立 grant/operation 表与恢复线索，不能撤销正式报告或已产生的通知。先关闭开关，保留数据库结构和审计；只有另行获批的数据恢复方案才能考虑破坏性 schema 操作。
- 通知使用现有持久站内 Notification，不承诺邮件/worker 恰好一次。故障后先按 operation_id 核对同事务结果及通知记录，不盲目再执行一个新提案。
