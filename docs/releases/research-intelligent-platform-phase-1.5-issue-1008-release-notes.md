# 科研智能平台 Phase 1.5：1008 反馈发布说明

## 4.23.0：二轮人工反馈收尾

- IA v2 一级入口由“研究链”更名为“项目与课题”；课题与项目管理视图共享唯一“创建科研项目”主按钮，点击后进入项目视图并打开原创建对话框，报告与成果视图保持各自唯一主操作。
- 报告视图移除“上传课题资料 / 登记成果”；成果视图继续提供“登记成果”与成果附件能力，顶层课题资料操作组件删除。
- 项目作用域导航仅保留一个最近项目列表返回；报告、研究链、阶段、阶段资料和节点 Agent 详情页分别增加唯一最近上级返回。
- 反馈截图上传收敛为一个“添加截图”按钮加隐藏文件输入；“我的反馈”日期支持任意、近 7 天、近 30 天与自定义区间。
- 反馈管理改为全高双栏：左侧筛选与记录列表，右侧稳定显示快照占位或完整描述、上下文、截图、历史与处置表单。
- 新增学生具有主组织归属时直接创建科研项目与周期报告的 API 契约；无组织关系仍由科研 ACL 拒绝。
- 验证：Web 组件 44 个文件、165 项通过，类型检查与生产构建通过；科研浏览契约 18 项通过；反馈契约 19 项通过；二轮浏览器验收业务控制台错误 0。

## 4.22.2：组合筛选基线与收尾回归

- 补充学生、直接导师、主 PI、工作区管理员四类身份及两个组织单元的可复现项目/报告组合筛选契约。
- 固定默认范围、`mine=true`、组织、责任人、关键词和日期组合的结果断言，并记录脱敏验收证据。
- 完成 Web 组件、类型、格式、生产构建、API 契约、迁移漂移与 Django system check；不改变科研 ACL、报告审核状态机或正式快照语义。

## 4.22.1：反馈 HTTP/IP 兼容修复

- 修复 HTTP 或 IP 地址访问时浏览器缺少 Web Crypto `randomUUID`，导致反馈弹窗无法正常初始化或编辑的问题。
- 反馈请求仍优先使用标准 UUID；不可用时使用前端降级幂等键，失败重试保持同一键，服务端权限与去重契约不变。
- 补充缺失 `randomUUID` 的组件测试；反馈组件回归共 42 个文件、160 项通过。

## 4.22.0：反馈架构独立化修正

### 本次交付

- 将 4.21.0 的 Plane → AI4MS 反馈 BFF 替换为 Plane 内建闭环：新增 `ResearchFeedback` 与 `ResearchFeedbackScreenshot`，反馈记录、状态历史和权限判定全部保存在 Plane。
- 截图复用 `FileAsset` 与 Plane S3，新增 `FEEDBACK_SCREENSHOT` 专属类型；workspace/project/user、legacy file-assets 与 duplicate-assets 等通用资产创建、复制、下载、修改、删除和恢复入口对反馈截图全部 fail-closed，浏览器只经反馈专属接口读取流式截图。
- 保留现有提交、我的反馈和反馈管理界面；前端改用专用 `ResearchFeedbackService` 与 `researchEndpoints`，接口路径和响应结构保持兼容。
- 管理列表补齐读取中、失败重试、关键词/模块 300ms 防抖、处置上下文、本地化时间和截图失败占位；反馈 Tab 支持方向键切换。
- 每用户反馈提交限流为 5 条/小时，活动截图投影配额 100 MB，同用户提交使用 cache 原子锁；缓存不可用 fail-closed。
- 管理页在身份加载前不发起管理请求，普通成员直达显示中性权限态；列表刷新后清除陈旧选中记录。
- 工作区成果按 `published_at` 过滤和展示“发表/授权日期”，创建项目选项批量解析，报告创建弹窗补齐模板选择。
- 新增 `legacy_feedback_id` 内部映射与 `import_research_feedback_from_ai4ms` 管理命令，支持 dry-run 预检与幂等导入 4.21 历史数据。
- 移除 Plane 侧 `AI4MS_FEEDBACK_BASE_URL` 与 `AI4MS_FEEDBACK_SECRET`；本能力部署不依赖 AI4MS 后端。

### 配置与迁移

- Django 迁移顺序：`0163_report_image_snapshots` → `0164_formal_report_context` → `0165_research_feedback`。
- 备份必须同时覆盖 Plane PostgreSQL 与 S3 bucket。
- 4.21.0 若已在 AI4MS MongoDB 产生 `platform=plane` 反馈，默认必须按 `docs/operations/research-feedback-ai4ms-migration.md` 执行 dry-run；记录数为 0 才可直接发布 AI4MS 2.0.0 清理，记录数大于 0 必须先执行幂等导入并验收。
- 2026-10-09 发布例外：用户明确取消生产 MongoDB 凭据门禁并授权直接发布，因此本次未执行生产 dry-run、AI4MS MongoDB/GridFS 备份和导入验收。AI4MS 源数据保持只读；取得凭据后必须补做预检，记录数大于 0 时继续按 runbook 导入并验收。
- API 镜像新增 `pymongo>=4.14,<5`，仅用于该只读源迁移命令。
- API 测试依赖固化到 `Dockerfile.test`，测试 compose 不再在每次运行时联网安装依赖。

### 验证

## 4.21.0：1008 问题补齐（历史版本）

### 本次交付

- 报告列表默认加载当前用户有权查看的全部报告；“仅看我的”改为显式筛选，并保留 URL 筛选回放。
- 报告和科研项目创建表单移入独立对话框，列表工具栏只保留浏览与筛选控制。
- 报告附件支持 PDF、Markdown、图片、DOC/DOCX、XLS/XLSX、PPT/PPTX、CSV/TSV；办公文件按工作区大小限制、扩展名、MIME 与文件头签名校验。
- 报告详情收敛为「报告正文 + 附件」两个主区域，正文统一复用 `DocumentEditor`，支持本地 JPEG/PNG/WebP/GIF 正文图片、Markdown 导入同步和真实 S3 对象校验。
- 报告与成果提供同页双视图和各自筛选；科研项目与研究链支持人员搜索、关键词、日期预设、范围筛选、服务端分页和 URL 回放。
- Agent 新增受控正式报告内容接口：固定版本正文、附件清单、来源与版本展示，并逐次校验 ACL、撤销、过期与版本变化。
- 该版本反馈闭环曾采用 Plane BFF 调用 AI4MS 专用 API，并使用 AI4MS MongoDB/GridFS 保存权威记录；该架构已被 4.22.0 取代，仅作为历史发布事实保留。
- `docs/` 按职责重组为 `product/`、`plans/`、`architecture/`、`contracts/`、`operations/`、`releases/`、`archive/`、`assets/`、`evidence/`。
