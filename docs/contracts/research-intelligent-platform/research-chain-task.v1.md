# 科研任务指派与成员资格契约

## 负责人资格

科研任务负责人必须先加入任务所属课题。账号、工作区成员关系、课题成员关系均须有效且未删除，工作区和课题角色须为成员（15）或管理员（20）。组织成员、上级组织成员、导师或只读访问身份本身不授予指派资格；跨组织的有效课题成员可以被指派。

`GET /api/research/workspaces/{slug}/chains/{chain_id}/assignable-users/` 保持 `research-chain-assignable-user.v1` 的响应字段和组织分组，所有候选人均满足上述成员条件。组织信息仅用于展示。

任务创建、改派与提交使用相同的成员资格校验，并在写事务内再次检查。直接提交非成员 ID 返回既有 `research_permission_denied` 错误（HTTP 403）。身份准入或父课题不可见时，继续返回现有 403/404，不暴露任务存在性。

## 任务响应

任务 `research-chain-task.v1` 新增只读布尔字段 `assignee_is_valid`。无负责人或资格失效时为 `false`。历史 `assignee`、`assignee_detail` 保留，不能把失效负责人伪装成未指派。列表、详情和写操作返回相同字段；客户端传入该字段不改变服务端判断。

提交能力同时要求当前用户为负责人、具有有效成员资格，且任务处于 `ASSIGNED` 或 `NEEDS_REVISION`。资格失效不授予新权限，也不删除历史活动。

## 历史任务与待办

- 待负责人处理的任务失效后，从负责人待办移除，发起人可见的待办标为 `BLOCKED`，下一步为 `ASSIGN`。
- 已提交任务继续审核，下一步为 `REVIEW`，不因负责人失效而改成待指派。
- 已完成、已取消任务保持历史记录。恢复有效成员关系后，未完成任务按原状态自动恢复资格与待办。
- 管理者应在课题成员入口补充成员或重新指派。系统不自动添加成员或扩大课题可见性。

## 只读审计

```bash
python manage.py audit_research_task_assignees <workspace_slug> --json
```

输出 `workspace` 和 `tasks`，每项包含任务 ID、标题、状态、课题 ID/名称、研究链 ID、负责人 ID/姓名及失效原因。扫描未删除的历史和进行中任务，不修改指派、成员、状态或审计事件。发布前应由管理者核对结果；本变更无需数据库迁移。
