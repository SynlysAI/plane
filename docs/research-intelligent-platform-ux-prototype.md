## 1. 设计原则

- Plane 保持统一门户；用户不需要先理解多个后端系统的边界。
- 当前课题和当前节点始终固定显示，所有 Agent、文件、知识库和待办操作都继承该上下文。
- AI 输出先进入草稿或待确认状态，用户确认后才写入研究链正式快照。
- 过程信息比最终结果更重要：工具调用、验证、导师意见、审批和数据变化都能回放。
- Plane 根据课题、节点和角色自动装配 Agent 能力；用户不手动安装、勾选或注册 Synlora 插件。
- RAGPortal 是资料入库入口；WeKnora 作为已部署的内网知识服务由 RAGPortal 使用，用户不直接接触 WeKnora。
- 外部服务异常时保留人工记录路径，界面明确显示降级原因。

## 2. 科研信息架构收敛与研究链位置

研究链是“科研”模块的核心过程入口。`research_ia_v2` 默认开启，旧科研业务入口不再平铺展示，而是收敛为四个一级入口；权威对象、既有 API、导航能力 key 和对象 ACL 不因入口收敛而改变。开关关闭时，现有导航和页面行为完整保留。

### 2.0 当前界面问题与收敛结论

Phase 1 已完成 Chain、Agent、RAGPortal 和过程数据闭环，但界面仍按旧 Phase 1 计划平铺科研入口。当前截图暴露的问题收敛为四类：

- 侧栏同时暴露科研总览、报告、提交汇总、科研项目、研究链、待我评审、办公审批、组织架构和系统管理，用户需要理解管理域与过程域边界。
- 科研总览混合管理统计、项目表格、报告汇总、阶段评审和审批入口，页面职责过宽。
- Chain 首页、项目列表和报告列表缺少统一容器，用户无法感知“科研项目和报告属于 研究链的保存视图”。
- 权限与降级状态存在原始 key/code 展示，基础可用性不足。

v1.4 的实施结论：不重写 Plane 视觉体系，只增加 `research_ia_v2` 呈现层开关、四入口侧栏、审批中心 Tab、科研管理 Tab、Chain 保存视图和显式兼容路由。

```text
Plane 门户
├─ 首页                         （保留，仅紧凑科研摘要卡）
├─ 草稿                         （保留）
├─ 我的工作                     （保留）
├─ 便签                         （保留）
├─ 工作区
│  ├─ 项目                      （保留，普通 Plane 项目管理）
│  ├─ 添加项目                  （保留，普通项目创建入口）
│  └─ More                      （保留，其他通用入口）
└─ 科研
   ├─ 科研总览                  （跨课题工作台）
   ├─ 研究链             （课题与科研过程主线）
   ├─ 审批中心                  （评审、审核、Agent 与办公审批）
   └─ 科研管理                  （管理域聚合入口）
```

信息架构规则：

- **科研总览**负责跨课题统计、提交汇总、最近活动和待办索引；不复制 Chain 时间线。
- **研究链**负责课题、成员、节点、快照、事件、报告与成果、实验记录、外部引用、Agent 协作和过程回放。
- **审批中心**统一承载阶段评审、报告审核、Agent 审批和办公审批；与课题关联的审批可跳回节点上下文。
- **科研管理**聚合组织与人员、账号与系统、模板、身份与账号绑定、平台配置、审计记录和系统集成；Tab 按既有管理能力逐项显示。
- 普通 Plane 的首页、草稿、我的工作、便签、工作区项目、添加项目和 More 保持原路由、权限和行为不变。

科研导航的最终显示仍由现有“工作区子开关 × 用户能力 × 对象 ACL”三层规则决定；四入口只是前端呈现分组，不改变已有 `overview`、`reports`、`projects`、`approvals`、`system`、`platform`、`audit`、`integrations` 和 `research_chain` 的语义。

### 2.1 目标路由与旧入口兼容

下表省略 workspace slug；当前公共科研空间对应 `/public/research/...`。报告详情、项目详情等对象级深链保留，不在本轮强制改址。

| 目标入口   | 目标路由               | 说明                                                            |
| ---------- | ---------------------- | --------------------------------------------------------------- |
| Plane 首页 | `/`                    | 仅展示紧凑科研摘要卡，完整工作台进入科研总览                    |
| 科研总览   | `/research/`           | 跨课题统计、`report_submission` 保存视图、最近活动和待办索引    |
| 研究链     | `/research/chains/`    | 课题、成员、节点、报告与成果、实验记录、外部引用和过程回放      |
| 审批中心   | `/research/approvals/` | `stage_review`、`report_review`、`agent_approval`、办公审批队列 |
| 科研管理   | `/research/settings/`  | 组织、系统、模板、身份、平台、审计、集成 Tab                    |

具体课题使用 `/research/chains/{chain_id}/`，节点使用 `/research/chains/{chain_id}/nodes/{node_id}/`。开启 `research_ia_v2` 后，旧列表路由按以下规则兼容：

| 旧路由                      | 目标路由                               |
| --------------------------- | -------------------------------------- |
| `/research/projects`        | `/research/chains?view=projects`       |
| `/research/reports`         | `/research/chains?view=reports`        |
| `/research/reports/summary` | `/research?view=report_submission`     |
| `/research/reviews`         | `/research/approvals?tab=stage_review` |
| 管理配置旧路由              | `/research/settings/{tab}`             |

### 2.2 UI Ready 容器规格

```text
科研总览
├─ 范围筛选 / 统计周期 / 刷新时间 / 进入 研究链
├─ 我的待办 · 待审批 · 待确认 · 阻塞与降级
├─ 我的课题摘要 · 报告提交汇总 · 近期成果
└─ 最近活动索引；管理统计仅管理员/PI 可见

研究链
├─ Tab：课题 / 项目管理 / 报告与成果
├─ 课题：创建、筛选、归档、打开课题详情
├─ 项目管理：复用既有 Project 权威对象和列表
└─ 报告与成果：复用 PeriodicReport 权威对象和列表

审批中心
├─ Tab：阶段评审 / 报告审核 / Agent 审批 / 办公审批
├─ 队列显示来源、上下文、提交人、时间和主操作
└─ 课题关联审批可跳回 Chain 节点

科研管理
├─ Tab：组织与人员 / 账号与系统 / 模板 / 身份与账号绑定
│        / 平台配置 / 审计记录 / 系统集成
└─ 复用既有页面组件；平台配置在模块关闭时仍可恢复
```

容器规则：Tab 由既有 capability 与 section 过滤；无权限时不渲染；空态显示“暂无数据”，降级态显示中文原因、重试和人工记录路径，不展示原始 error key。

### 2.3 UX 覆盖矩阵与阶段边界

| UX 区块            | Phase 1 交付                                                                                   | Phase 2 增量                                      | Phase 3 增量                       |
| ------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------- |
| Plane 首页紧凑摘要 | 必做：课题/待办/快照摘要、入口、权限过滤和降级态                                               | 替换为真实专业运行摘要                            | 增加治理和配额摘要                 |
| 科研总览           | 必做：范围筛选、待办索引、提交汇总、课题摘要、近期成果、最近活动和管理统计                     | 填充 Job、DataAsset、专业组件状态和运行回执       | 增加治理统计和开放状态             |
| 研究链列表         | 必做：课题、项目管理、报告与成果保存视图                                                       | 项目/报告视图补充专业运行和外部资产上下文         | 不重构骨架                         |
| 研究链课题页       | 必做：固定上下文条、七个页面 Tab、主链可视化、循环关系、成员、报告/实验/外部引用和回放         | 外部运行节点、DataAsset、自动 ELN 外部段          | 治理 gate 和结题/转化状态          |
| 六段式节点详情     | 必做：输入、AI 动作、中间产物、验证、人类决策、输出                                            | 填充真实 Tool Call、Job、RunEvent 和回执          | 增加策略命中、伦理/IP 和可复现状态 |
| Agent 工作台       | 必做：Context 条、自动装配分组、消息流、结构化工具卡、审批抽屉、产物抽屉、Trace 面板和状态矩阵 | 专业工具、异步 Job、风险分级和 DataAsset 结果确认 | 治理提示、配额、审计和管理员配置   |
| 审批中心           | 必做：四个 Tab、统一队列卡片、来源、上下文、主操作和 Agent 审批                                | Job 阻塞、恢复、运行回执和专业审批                | 高风险治理审批和策略版本           |
| 科研管理           | 必做：七个 Tab、命名统一、平台配置回退、审计/集成状态                                          | 科研模板库、真实连接健康和运行回执                | 治理策略、保留期和审计导出配置     |
| 专业组件入口       | 必做：占位卡片、能力摘要、降级原因和最近同步时间                                               | 接入 SpecLabOS、PolyAgent、SpecAgent 真实状态     | ScienceDiscovery Worker 和开放能力 |
| 基础 UX 质量       | 必做：卡片/间距/按钮层级、响应式、键盘可达、aria、中文状态文案                                 | 仅针对新增运行卡片做小型视觉调整                  | 仅针对治理组件做小型视觉调整       |

Phase 1 允许占位的内容：SpecLabOS、PolyAgent、SpecAgent 专业组件入口、Job 状态、DataAsset 详情、自动 ELN 外部段、治理和配额。占位必须说明“未接入/未配置/后续阶段开放”，不得显示伪造的成功运行、真实结果或已完成审批。

### 2.4 核心状态矩阵

| 状态             | 适用区域                               | Phase 1 呈现要求                                   |
| ---------------- | -------------------------------------- | -------------------------------------------------- |
| loading          | 所有数据区                             | 骨架屏或明确加载文案，禁止长时间空白               |
| empty            | 列表、待办、快照、工具、产物、Trace    | 说明当前范围没有数据，并提供下一步动作             |
| forbidden        | 页面、卡片、工具和导出                 | 中文权限说明，不泄露无权限对象标题、计数或正文     |
| degraded         | RAGPortal、Synlora、专业组件、外部待办 | 中文原因、最近同步时间、重试和人工记录路径         |
| streaming        | Agent 消息与事件                       | 连接状态、停止生成、最后事件序号                   |
| waiting approval | Agent 工具、审批中心                   | 显示申请人、scope、风险、原因和批准/拒绝动作       |
| saving           | AI 产物、快照和人工确认                | 按钮 pending，重复提交被禁止，失败保留草稿         |
| error            | API、页面、动作、上传、保存            | 分类文案、重试/返回/人工路径，不显示原始 error key |
| expired          | Context、授权、外部链接                | 说明过期时间，提供刷新授权或重新进入来源系统       |
| closed           | Agent session、外部任务                | 保留只读结果或明确关闭原因，不显示可写操作         |

```mermaid

    subgraph Student[学生主线]
        A[科研总览] --> B[选择/创建研究链课题]

        L[科研管理] --> M[组织 · 身份 · 模板 · 平台 · 审计 · 集成]

    end
```

交互规则：

- 点击课题进入该课题 Chain；点击待办进入审批中心对应队列，并可继续跳到节点或审批抽屉。

- 无权限课题不显示标题、计数或快照摘要。
- RAGPortal、Agent 或专业组件不可用时，入口保留但显示“服务暂不可用”和最近同步时间。

### 自动装配摘要

Agent 面板在消息流上方展示只读装配结果：

- 当前课题、节点和 persona。
- 自动可用插件与工具，按“已授权 / 需确认 / 不可用”分组。
- 每个工具显示 capability scope、风险等级、输入摘要、确认状态和 Trace 链接。
- 不可用能力显示具体原因：未配置、无权限、健康异常、策略阻断或需要导师/PI 审批。
- 用户不能在 Plane 插件内手动扩大 Synlora 扩展范围；需要新增能力时跳转科研管理或联系 Workspace Admin。

插件状态：

```mermaid
stateDiagram-v2
    [*] --> initializing
    initializing --> loading_context
    loading_context --> ready
    loading_context --> forbidden
    ready --> streaming
    streaming --> waiting_approval
    streaming --> ready
    waiting_approval --> streaming: 确认
    waiting_approval --> ready: 拒绝
    streaming --> saving: 保存产物
    saving --> ready
    saving --> error
    ready --> degraded: RAG/Agent 服务异常
    ready --> expired: Context 过期或撤权
    streaming --> expired: Context 过期或撤权
    expired --> ready: 刷新授权成功
    degraded --> ready: 重试成功
    ready --> closed: 切换课题/关闭插件
```

## 7. 关键交互确认点

本原型建议确认以下产品选择：

| 交互点     | 当前建议                                                         |
| ---------- | ---------------------------------------------------------------- |
| 信息架构   | 开启 `research_ia_v2` 后仅保留四入口；关闭时完整回退旧导航       |
| Agent 位置 | 课题页右侧工作台，节点详情可扩展为双栏页面                       |
| 上下文显示 | 顶部固定显示课题、节点、授权资源数量和 Context 有效期            |
| 能力装配   | Plane 自动显示 persona、插件、工具和拒绝原因，不提供手动扩大范围 |
| 工具卡     | 显示 capability scope、风险等级、确认状态和 Trace 链接           |
| AI 草稿    | 先进入产物抽屉，必须人工选择保存类型并确认                       |
| 导师参与   | 从审批中心进入报告审核、阶段评审或 Agent 审批，并可跳回节点      |
| RAG 入库   | 用户从 Plane 进入 RAGPortal 上传；WeKnora 对用户透明             |
| 研究链     | 作为科研过程主入口；主链横向展示，节点详情纵向展示事件和快照     |
| 降级体验   | 提供“刷新授权 / 人工记录 / 稍后重试”，并明确能力不可用原因       |
| 移动端     | Agent、Trace、工具和快照采用上下堆叠布局，不压缩桌面双栏         |

## 8. Phase 映射

- Phase 0：确认 `research_ia_v2`、兼容路由、插件 manifest、状态字典、课题上下文和 BFF 边界。
- Phase 1：交付绝大部分 Plane 所属 UI/UX：四入口 IA、Plane 首页紧凑摘要、科研总览、研究链课题页、六段式节点详情、Agent 自动装配工作台、六类快照、审批中心、科研管理、跨组件待办索引和基础状态矩阵。专业运行、治理和配额只保留真实占位/降级态。
- Phase 2：不重构页面骨架，只在 Phase 1 容器中填充真实专业能力：Job/RunEvent/DataAsset、实验/分析工具卡、风险分级、运行回执、科研模板库、集成健康和自动 ELN 外部段。
- Phase 3：不新增科研一级入口，只在既有容器上叠加治理 banner、风险审批、配额、审计跳转、写作/评审 Agent、结题/转化 gate，并评估兼容路由去留。
