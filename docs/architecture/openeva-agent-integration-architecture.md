## 0. 总览：三条集成线

OpenEVA 与 Agent 的交互收敛为三条互补的集成线，各自解决不同的问题：

```
+---------------------------------------------------------------+
|                     OpenEVA（Plane 科研平台）                   |
|                                                               |
|  +------------------------+      +------------------------+   |
|  | Agent 插件（BFF 层）    |      | 专业工具 MCP 网关       |   |
|  | agent-plugin.v1 契约   |      | mcp_gateway（17 工具） |   |
|  +-----------+------------+      +-----------+------------+   |
+--------------|-------------------------------|----------------+
               | 线 2 / 线 3                   | 线 1
               v                               ^ MCP(HTTP+Bearer)
    +---------------------+        +--------------------------+
    | 线 2：本地 Agent(SD) |------->| 线 2：本地 Agent(SD)     |
    | 单用户·用户级连接    |  线 1  | 作为 MCP 客户端调用网关   |
    +---------------------+        +--------------------------+
               ^
               | 线 3（对照）
    +---------------------+
    | 线 3：多租户 Agent   |
    | （Synlora 云端）     |
    +---------------------+
```

| 线       | 方向                            | 一句话定位                                              | 状态                                        |
| -------- | ------------------------------- | ------------------------------------------------------- | ------------------------------------------- |
| **线 1** | 本地 Agent →（MCP）→ OpenEVA    | 本地 Agent 以 MCP 客户端身份调用 OpenEVA 侧专业工具网关 | 代码已实现（P7），部署联调待环境            |
| **线 2** | OpenEVA →（插件）→ 本地 Agent   | OpenEVA 的科研智能体插件经 BFF provider 接本地 SD       | 已实现并联调通过（P1–P6 + UI 唯一入口收口） |
| **线 3** | OpenEVA →（插件）→ 多租户 Agent | 同一插件契约接 Synlora 云端多租户运行时（平台默认）     | 既有实现，本期不动                          |

## 1. 线 2｜OpenEVA —插件→ 本地 Agent（当前主线）

**定位**：学生在 OpenEVA 界面提问，问题经 BFF 交给其本人的本地 ScienceDiscovery 执行，回答与留痕回流 OpenEVA。适合长任务、本地数据、重型科研执行。

### 1.1 职责边界

| 关注点                       | 归属                                                           |
| ---------------------------- | -------------------------------------------------------------- |
| 谁能用、能看哪个节点/文件    | OpenEVA（BFF 权限校验 + 上下文装配）                           |
| 课题/节点/时间线留痕         | OpenEVA（ResearchChainEvent，source_system=SCIENCE_DISCOVERY） |
| 会话执行、模型路由、工具沙箱 | 本地 SD（单用户自治）                                          |
| 连接信息（地址/令牌）        | 学生本人，经设置页「智能体后端」自助配置，令牌 Fernet 密文落库 |

### 1.2 鉴权与路由

- **SD 侧**：单 Bearer token（学生自己的实例自己的钥匙）
- **OpenEVA 侧**：workspace 治理开关 `research_agent_user_backend_enabled`（默认关）+ SSRF 网段白名单
- **会话路由**（两级，无环境变量后门）：治理开关开且用户连接启用 → SD；否则 → Synlora（线 3）
- 会话创建时钉死 `backend_connection`，后续轮询/审批/文件/产物全部按会话记录路由

### 1.3 数据流

学生提问 → BFF 权限校验/装配 → （文件）multipart 转传 SD 工作区（sha256 对账）→ POST SD /runs 异步拿号即回 → 前端指数退避轮询 getEvents → BFF 拉增量 → 事件映射/幂等投影 → 流式渲染 + Chain 留痕；permission.required → 内联审批卡（三值枚举桥接）续跑至终态；artifact.upserted → 产物卡（代理下载 / 保存到节点回指 SD 原件）。建会话时四插件人设目录幂等下发为 SD specialist，按节点类型装配 specialistId。

### 1.4 演进

- 技能库整包导入（方法论较长时独立成库）
- 节点资料上传双写（RAGPortal + SD 工作区）
- workspace 级共享 SD 连接（互信小组场景，需评估隔离补偿）

## 2. 线 1｜本地 Agent ←MCP→ OpenEVA

**定位**：与线 2 方向相反的补给线——本地 SD 里的智能体需要 OpenEVA 侧的专业计算能力（谱图解析、高分子预测、文献检索）时，以 MCP 客户端身份调用 OpenEVA 部署的专业工具网关。

### 2.1 形态

- 网关服务：`Synlora 仓库 apps/web/backend/mcp_gateway`（独立 uvicorn 进程，默认 :8090）
- 直接**复用** Synlora 插件工具模块（13 个：spec 核磁 3 + poly 5 + sciverse 5）+ 谱图异步任务 4 工具，零移植漂移
- MCP over Streamable HTTP（initialize / tools/list / tools/call），单 Bearer 鉴权

### 2.2 鉴权与部署约束

- **上游凭证集中在网关**（Spec/Poly/Sciverse 的地址与密钥全部走网关环境变量），永不下发到学生 SD
- 学生 SD 经 `POST /api/mcp/servers` 注册网关（transport http + Bearer headers + timeoutSeconds=600 适配 350s 级慢任务）
- 网关网络位置需同时可达 AI4MS 内网服务与公网 Sciverse（校园内网部署）

### 2.3 与线 2 的关系

线 2 负责把会话流量接到本地 SD；线 1 负责让该 SD 里的会话「有专业工具可用」。两线独立演进、互不依赖：没有网关，SD 会话仍可用原生能力；没有线 2，SD 也可经自己的网页用网关工具。

## 3. 线 3｜OpenEVA —插件→ 多租户 Agent（Synlora，平台默认）

**定位**：云端多租户通用 Agent Runtime，全员共享、零自助配置，作为未配置本地连接时的默认回落。

### 3.1 与线 2 的同构与差异

| 维度     | 线 3（Synlora）                              | 线 2（本地 SD）                            |
| -------- | -------------------------------------------- | ------------------------------------------ |
| 插件契约 | 同一套 `agent-plugin.v1`（前端零差异）       | 同左                                       |
| 连接粒度 | workspace 级（`ExternalSystemConnection`）   | 用户级（`ResearchAgentBackendConnection`） |
| 身份     | delegated token 替用户换临时票（多租户隔离） | 单 Bearer token（一人一实例天然隔离）      |
| 消息模式 | 同步等待（现状）                             | 异步取号 + 增量轮询                        |
| 治理     | workspace 管理员配置                         | 治理开关 + SSRF 白名单 + 学生自助          |

### 3.2 演进

- 吸收线 2 的异步化经验（同步等待对长任务不友好），评估 Synlora 侧 run 异步化
- 工具白名单/persona 装配体系在多租户侧继续生效；SD 侧以 specialist/技能库近似

## 4. 三线共存：会话路由总图

```
学生发起 Agent 会话（OpenEVA 节点详情）
        |
        v
 resolve_science_discovery_connection(workspace, user)
        |
   +----+---------------------------+
   | 治理开关开 且 用户 SD 连接启用  | 否则
   v                               v
 线 2：本地 SD                 线 3：Synlora（默认）
 （会话钉死该连接）            （workspace 连接）
   |                               |
   +----> 统一 agent-plugin.v1 事件流 / 审批 / 文件 / 产物 <----+
        （前端与留痕对三线完全同构，source_system 区分来源）
```

设计原则：**掉线不静默换线**——SD 不可达时明确降级报错，由学生自行修复或停用连接回落；路由只看意图（配置与开关），不探测在线状态。
