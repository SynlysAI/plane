# 科研 MCP 剩余内容验收计划

状态：2026-10-17 已执行并完成当前能力范围验收。基线是同日已完成的本地 Plane × Codex 验证；本轮使用本地 Plane，未启动 ScienceDiscovery 或其他外部 Agent 服务，未运行 Docker 测试栈、未构建镜像。

结果：前四类元数据通过、正文未实现；Agent 公开投影正文通过。后端 79 项、独立代理 5 项、真实接口 71 项通过，Codex 三轮实际调用 21 次。验收发现的问题已修复，新增历史任务关联约束迁移 0181 并在本机备份后应用。详见 [验收摘要](../../docs/operations/research-mcp-v21-acceptance.md)。原始证据保留在开发机忽略目录，以下保留执行口径和用例安排。

## 一、先固定对象和能力范围

| 业务名称     | 当前 MCP kind      | 当前支持                                             | 本轮验收终点                                             |
| ------------ | ------------------ | ---------------------------------------------------- | -------------------------------------------------------- |
| 论文稿件评审 | paper_review       | 节点评审记录的 ID、状态、current_version_no 等元数据 | 列表与版本号准确；正文调用明确拒绝                       |
| 阶段材料     | stage_material     | 已关联且当前用户有权限的材料元数据                   | 关联与材料 ACL 同时生效；不读取 Page 草稿或材料正文      |
| 课题附件     | topic_material     | 已上传、未删除、与节点明确关联的附件元数据           | 只显示符合条件的附件；不提供文件字节、下载授权或解析正文 |
| 外部引用     | external_reference | 已关联且来源 ACL 允许的本地引用元数据                | 来源不允许或无法判定时拒绝；不访问外部 URL               |
| Agent 事件   | agent_event        | 绑定节点的存储事件及公开内容投影                     | 公开内容可溯源；内部推理及未授权字段不泄露               |

名称说明：当前 `paper_review` 是挂在 PAPER_WRITING 节点的稿件评审流程，不是 LiteratureEntry 文献条目。如果业务要求的是文献阅读评价、文献笔记或文献综述，需要另列对象映射与 MCP 开发项，不能用 paper_review 的测试覆盖替代。以下按当前 paper_review 模型安排。

前四类的 `read_research_resource` 对“已授权且确实存在”的对象应返回 `unsupported_content`；REST 为 422，MCP 为工具错误。对无权或不关联的对象，应先拒绝访问，不能因正文不支持而泄露对象存在。

## 二、测试数据与凭据准备

使用独立演示工作区，补建论文写作节点 C；保留分析节点 A 和隔离节点 B。不得把已有 ANALYSIS 节点改为论文写作节点来绕过模型约束。

准备四种身份/凭据：有节点及资源权限的用户、能看节点但不能看某份材料/外部引用的用户、同工作区无课题权限的用户、绑定单节点的短期 grant。前一轮临时凭据已撤销，本轮重新签发；真实凭据不进入报告和模型提示词。

每类至少包含：当前节点可见对象、同课题未关联对象（适用于需显式引用的类型）、同链其他节点对象、另一工作区对象、已删除或不可用对象。资源关联通过真实事件 refs、快照 resources/source_versions 建立；阶段材料和外部引用还覆盖科研任务支持的引用方式。

所有内容使用人工标记。对允许读取的 Agent 公开回答生成随机标记；只在隐藏字段中放置另一组虚构 canary 字符串，不使用任何真实密钥或模型内部推理文本。

## 三、逐类验收用例

### A. paper_review：评审元数据

1. 在 PAPER_WRITING 节点创建真实评审记录及 v1/v2 提交版本，核对列表中的 ID、状态和 current_version_no；不能只手工把版本号改为 2。
2. 当前节点列表只能列出属于该节点、链和工作区的评审；已删除评审、其他节点评审不应进入列表。
3. 个人 Key 与当前节点 grant 的结果符合各自范围；用当前 grant 指定其他节点和评审 ID，必须被拒绝。
4. 可见评审正文调用返回 unsupported_content；不能返回稿件附件、修改说明、评审意见或下载凭据。
5. 由受控准备动作把版本从 v1 推进到 v2，重新读取列表，确认不复用旧元数据结果；不将 current_version_no 解释为已读取某个版本的正文。

通过标准：记录、状态、版本号与源对象一致；Codex 明确“能看到评审记录，未读取稿件及意见正文”。如果业务需要意见正文，该需求记录为待开发，不能标为本轮正文验收通过。

### B. stage_material：关联与材料 ACL

1. 为当前课题准备阶段实例和材料，分别建立事件、快照、任务引用；每种引用方式单独验证。
2. 同项目材料未关联到当前节点时，列表不显示，指定 ID 也不能读取。
3. 材料已关联，但调用用户无权查看材料时，列表及直接读取均不得泄露其信息。该用例要使用确实受材料 ACL 限制的账号，不能只使用 owner。
4. 覆盖从未提交草稿、已有正式版本后的新草稿、提交或接受状态，并与已有材料业务接口的可见性核对。标题等未纳入当前投影的字段不凭空列为已支持。
5. 对可见材料请求正文，返回 unsupported_content，不泄露对应 Page 的未提交正文；材料、父阶段或课题被删除/失去可见性后，不应继续暴露材料。

通过标准：节点关联和目标材料权限缺一不可；元数据状态准确；有 Page 不代表本版 MCP 已支持材料正文。

### C. topic_material：附件生命周期

1. 准备合法的 RESEARCH_TOPIC_MATERIAL 附件，以及未完成上传、is_deleted=true、软删除、不同 entity_type、其他课题和其他工作区附件。
2. 对已上传且已关联附件，核对 ID、文件名（attributes.name）、大小及 metadata_only 标记。
3. 未关联、上传未完成、已删除和非课题附件不能进入结果；在事件中伪造跨课题/工作区引用也不能绕过过滤。
4. 列出后撤销关联或删除附件，重新请求应按当前状态拒绝；不沿用之前的列表结果放行。
5. 正文读取明确拒绝；结果不得含存储密钥、内部存储地址或带授权参数的下载 URL。只做元数据验收时使用明确标记的人工投影；不据此宣称已验证真实文件上传、下载或解析。

通过标准：附件元数据范围和生命周期过滤正确；Codex 不根据文件名生成“文件内容摘要”。

### D. external_reference：来源授权与不可用状态

1. 建立来源 ACL 为 public、指定用户、指定组织、明确不包含当前用户以及空 ACL 的引用，并逐个关联到节点。
2. 核对列表中的 source_system、external_id、external_type、title 和 status；public 引用仍不能跨节点关联范围或工作区读取。
3. 来源授权与节点权限分别撤销，重新请求均应拒绝；来源无法判定时默认拒绝，不回退到课题 owner 的权限。
4. 为 ACTIVE、UNAVAILABLE、DEGRADED、REVOKED 分别固定业务规则：不可用/降级对象至多保留明确状态的历史元数据，不冒称源端实时可用；REVOKED 不得继续作为有效可读引用暴露。若当前实现不满足该口径，记为缺陷并修复。
5. source_url 使用本地可计数的演示地址，确认 MCP 列表和正文请求不会触发抓取；只允许返回当前声明的元数据字段，不泄露 metadata 内的凭据或连接配置。
6. 正文读取 unsupported_content，Codex 明确未查询到外部原文。当前只验证本地存储的 acl_hint 执行效果，不能宣称已核验源系统的实时 ACL 或同步可靠性。

通过标准：默认拒绝、权限变化即时生效、撤销不泄露、无任意 URL 请求；本地引用状态和源端实时状态清楚区分。

### E. agent_event：公开事件与敏感内容边界

1. 通过受控测试准备动作创建本地会话及持久化事件，不调用真实 SD/Synlora 创建会话或运行模型。覆盖当前节点、其他节点、其他工作区、软删除会话及同节点不同用户会话。
2. 先与既有会话业务权限对齐“同节点其他用户的公开事件是否可共享”。不能默认节点可见就能读所有私有会话；若原有会话要求用户隔离，本 MCP 也必须遵守。
3. 公开事件核对 event_type、seq 和允许公开的 content/summary/name/toolCallId。按事件 ID 核对分页完整性；多 run 的 seq 可以重复，不能按 seq 全局去重。记录当前列表排序规则，不把创建时间顺序冒称运行序号顺序。
4. 在 reasoning、thinking、headers、credentials、工具参数及原始结果等非公开字段放入虚构 canary，确认列表、正文、错误响应和审计元数据均不出现这些 canary。
5. 重点增加“reasoning/thinking 类型事件把文本放在通用 content 字段”的用例，不能仅验证同名字段被过滤。内部事件应排除或只保留明确允许的非敏感元数据；不允许以 content 字段名为由返回内部推理正文。发现失败按阻塞缺陷处理。
6. 验证长公开回答的分段拼接、哈希、参数校验及编号版本限制；事件为追加记录，不能通过覆盖原事件制造更新场景。
7. 区分历史内容与认证生命周期：会话关闭后，有权限的个人 Key 是否能读取历史公开事件按业务规则验证；原会话已撤销的 grant 一律拒绝。删除会话后，事件不能借历史引用继续暴露。

通过标准：Codex 读出公开回答的随机标记及来源事件 ID；隐藏 canary 零泄露；同节点跨用户、跨节点和跨工作区范围均符合既有业务权限。

## 四、共用协议和分页用例

- REST 与 HTTP MCP 对同一身份、参数返回相同的可见对象集合；MCP 错误需检查 isError，不能只看 HTTP 200。
- 五类各有小页续读用例，核对无重复、无遗漏。额外对一个有 ACL 过滤的类型准备超过 200 条无权候选及后置可见对象：即使当前页为空且 has_more=true，续页仍必须找到后续可见对象。
- 游标不能跨 kind、节点、用户、grant、筛选条件和 limit 使用。
- 列表可见性、直接按 ID 访问、事件/快照中的嵌套引用三种入口同时检查，避免正文被拒绝但摘要或引用仍泄露。
- 重新授权时必须使用新凭据；旧的到期/撤销凭据不能因同时提供有效个人 Key 而回退。

## 五、执行顺序

1. **准备阶段**：冻结上述范围和业务可见性规则；补齐测试节点、对象及对照关系；生成新凭据。
2. **确定性检查**：先补后端契约测试和真实 REST/HTTP MCP 断言。优先做 Agent 敏感内容、来源撤销、材料 ACL 和跨范围用例；发现问题修复后只重跑相关检查及核心回归。
3. **Codex 业务验收**：只安排三轮模型问答，其他组合由脚本覆盖，减少重复模型调用。
   - 第一轮：列出当前节点的四类元数据，逐项说明哪些正文尚不可读，不提供未经读取的内容摘要。
   - 第二轮：读取 Agent 公开事件，引用事件 ID 与 seq，准确复述事先未告知模型的随机标记；隐藏 canary 不得出现。
   - 第三轮：用节点 grant 实际尝试其他节点、未关联资源及来源无权对象，核对真实拒绝，不能只由模型口头声明无权。
4. **收尾**：核对测试业务数据未发生越权修改；撤销临时凭据并复查拒绝；保留人工演示数据和脱敏证据；更新覆盖矩阵。

契约测试继续使用独立测试数据库与进程内缓存，避免测试 fixture 清空开发 Redis。沿用本地既有镜像，不启动外部业务系统；验收过程中的模拟外部请求不等于真实外部系统联调。

## 六、通过条件及交付物

逐类标注“元数据通过”“公开正文通过”“正文未实现”“发现缺陷待修复”，不要用总测试数掩盖未实现功能。前四类只有完成相应正文开发后，才能安排正文成功读取验收。

以下任一情况阻塞本轮完成：跨权限数据泄露、Agent 内部推理或凭据 canary 泄露、撤销后继续读取、分页漏数据、错误声称已解析文件或已查询外部原文。

交付：五类覆盖矩阵、测试对象/关联清单、契约测试报告、真实接口断言、三轮 Codex 回答及脱敏调用记录、缺陷与修复记录、临时凭据撤销结果。现有核心用例必须继续通过，再把这五类加入“已验收”范围。
